# ADR-0003: 客户页面只加载当前摄像头组

## Status

Accepted

## Context

现有 Portal 会遍历全部摄像头并同时创建播放器。增加第二组后，一个绑定设备会尝试拉取四路直播，并与每设备两路限额冲突；回放也会同时索引和预缓冲全部画面，浪费家庭上行、服务器代理并发和手机资源。用户界面只需要在“院子/门前”等物理设备之间切换，每次显示同组两画面。

## Decision

Portal 的公开配置返回不含管理和录音字段的摄像头组。客户页面保存所有组元数据，但 `state.cameras` 始终只代表当前非空组、最多两路。切组必须依序停止旧组直播、终止录像索引请求、销毁回放/HLS/JSMPEG/WebRTC 并静音，再更新组和构建当前模式。

一个非空组时隐藏标签；空的预留组只在 Tailscale 管理页出现。所选组可在同源浏览器本地记忆，但不存在或变空时回退到第一个非空组。

## Consequences

### Positive

- 每个客户端任意时刻最多拉两路，符合现有限额。
- 切组释放旧连接，降低公网带宽、代理并发和移动端耗电。
- 直播与回放保持相同的组标签和双画面心智模型。

### Negative

- 切组需要重新建立媒体连接，会有正常的短暂加载时间。
- 客户无法同时查看两组共四路；这属于首版明确限制。
- 需要确保所有时间轴、全屏和后台恢复路径都引用当前组。

### Neutral

- 管理页仍可一次显示全部组的单次低清快照，不建立持续视频连接。

## Alternatives Considered

**同时创建四路并用 CSS 隐藏**：仍消耗连接和带宽，且会触发限额。

**提高每设备直播限额**：把资源问题扩大，无法解决回放并发和手机压力。

**每组独立 Portal**：重复状态、绑定和入口配置，运维成本高。
